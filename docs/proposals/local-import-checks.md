## Four fresh T2 cases

- **L01 desktop, 1440 × 1000:** choose a real authored directory with the browser folder input. Six metadata rows begin unchecked. Select four valid CSV/JSON/NDJSON files and one malformed JSON, leaving a 9,999-value decoy unselected. Nested `north/sales.csv` and `south/sales.csv` keep distinct paths, IDs and bytes. Four imports succeed; the malformed file fails. Retry preserves every successful ID, byte/hash and timestamp. Reload restores the exact IndexedDB bytes. An ordinary new view/manual SQL panel aggregates only the four selected tables: **49 across six rows**.
- **L02 narrow touch-emulated, 390 × 844:** the same independent journey through real navigation and controls, in a fresh private context. This proves an emulated Chromium profile, not physical-device operation.
- **L03 explicit fault control:** intercept only creation of the first native readwrite transaction for Sift's owned `files` store. Attach a native `complete` listener before the application handler, then synchronously click the visible **Stop import** button. Record the actual completed event and native late-abort refusal. The committed first file must remain acknowledged; the queued second file must remain absent. Ordinary retry imports only the remaining file. This is injected commit-boundary evidence, not ordinary-user timing or a hard wall-clock guarantee for IndexedDB settlement.
- **L04 XLSX:** choose the authored two-sheet workbook through the actual file chooser. Import stays disabled until sheet inspection. Choose **South**, whose sole amount is 9, rather than North's 99; run actual local SQL and repeat the result after reload. Stored bytes, ID and selected sheet remain exact. A separately labelled missing-workspace-metadata fault removes only the disposable context's `sift.workspace.v1`; reload must restore the same file and keep both sharing flags off.

Fixture generation is dependency-free. The tiny workbook is authored OOXML in a stored ZIP; no third-party workbook writer is added. Native readonly IndexedDB/localStorage snapshots retain complete authored file bytes and metadata for independent inspection. Browser assertions use actual DOM controls; they do not invoke application engine internals or seed datasets. Successful import checks compare to independent fixture bytes, not the import implementation. The manual SQL result is observed in the panel inspector.

## Runtime and boundaries

The temporary, manual-only workflow remains pinned to `PREPARATION_SHA_REPLACED_BY_ROOT` until publication. One public Ubuntu 24.04 job has a 20-minute cap. Node **24.22.2**, the existing application lock and isolated Playwright/core **1.65.0** with exact SRIs are fixed. `npm ci --ignore-scripts` is followed by the reviewed `copy-duckdb.mjs` and unmodified `npm run build` (eve build, then Next). The current config has no standalone output; the runner uses real `next start`. It does not force `VERCEL` or suppress type errors. Existing build failures remain failures. No separate broad TypeScript compile is added.

Only same-origin static GET/HEAD resources and the empty `POST /api/session` are admitted. The unconfigured session must return the existing 503; only its exact resource-console diagnostic is separately accounted for. Unknown routes, PostgreSQL, eve/model paths, foreign origins, WebSockets, failed requests, other console/page errors and any outbound authored canary fail. No request is fulfilled with fake data. The session 503 is not agent acceptance.

Run paths, npm cache, browser tools, fixtures and temporary files belong to a 0700 runner root with a 0600 nonce marker; original HOME is retained. Build/install has a five-minute step, tools three minutes, and browsers seven minutes, leaving job headroom for checkout and final proof. Within the browser step, readiness plus work has a six-minute limit; browser work is at most five minutes, leaving a teardown reserve. The supervisor captures bounded server/browser original stdout/stderr, exit, EOF, descriptors and owned process-group closure, and refuses success if marked owned processes remain. TERM normally stops the owned production server; a browser deadline also requests browser shutdown and remains a failure. KILL fails. An external job kill remains an infrastructure limit.

Always-retained artifacts include full source manifests before/after, focused helper output, build/install logs, exact browser-tool lock, fixture originals/hashes, browser observations/screenshots and child cleanup. Source equality is required, not inferred from CI status. The readable-log packer fails on unexpected or oversized files; artifact upload is a separate retention channel. No local install, build, server, browser, dispatch or application test has been performed during preparation.
