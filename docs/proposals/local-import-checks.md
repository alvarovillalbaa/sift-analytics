## Runtime and boundaries

The temporary, manual-only workflow checks its exact dispatched `github.sha`; checkout, environment and both manifests must match that immutable commit. The main-only dispatch and read-only permissions remain. One public Ubuntu 24.04 job has a 20-minute cap. Node **24.22.2**, the existing application lock and isolated Playwright/core **1.65.0** with exact SRIs are fixed. `npm ci --ignore-scripts` is followed by the reviewed `copy-duckdb.mjs` and unmodified `npm run build` (eve build, then Next). The current config has no standalone output; the runner uses real `next start`. It does not force `VERCEL` or suppress type errors. Existing build failures remain failures. No separate broad TypeScript compile is added.

Only same-origin static GET/HEAD resources and the empty `POST /api/session` are admitted. The unconfigured session must return the existing 503; only its exact resource-console diagnostic is separately accounted for. Unknown routes, PostgreSQL, eve/model paths, foreign origins, WebSockets, failed requests, other console/page errors and any outbound authored canary fail. No request is fulfilled with fake data. The session 503 is not agent acceptance.

Before each reload and normal context close, every observed session request must have its own 503 response, `response.finished()` resolving to null and an actual `requestfinished` event under a finite deadline. Startup and each reload must produce the expected new request identity. Aborts, errors and timeouts stay fatal; the earlier aborted requests are not reclassified.

Run paths, npm cache, browser tools, fixtures and temporary files belong to a 0700 runner root with a 0600 nonce marker; original HOME is retained. Build/install has a five-minute step, tools three minutes, and browsers seven minutes, leaving job headroom for checkout and final proof. Within the browser step, readiness plus work has a six-minute limit; browser work is at most five minutes, leaving a teardown reserve. The supervisor captures bounded server/browser original stdout/stderr, exit, EOF, descriptors and owned process-group closure, and refuses success if marked owned processes remain. TERM normally stops the owned production server; a browser deadline also requests browser shutdown and remains a failure. KILL fails. An external job kill remains an infrastructure limit.

Next's exit 143 is accepted only for the expected server with exactly our TERM, null native signal and every existing identity/reap/EOF/group check. A bounded pre-launch process baseline and a start-tick cutoff recorded before installation/build identify exact unchanged pre-task processes. Task-created baseline processes still undergo marker inspection. Scan failures retain finite identities and errno; stable unreadable new identities fail. This is scoped ownership observation, not host-wide absence or an explanation of attempt 2's unattributed errors.
